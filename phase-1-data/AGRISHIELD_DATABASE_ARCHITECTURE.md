# AgriShield 360° — Database Architecture & Schema Specification

**Module:** AgriShield 360° / My Crop  
**Phase:** Phase 1C — Database Foundation  
**Target Platform:** KisanDost (Next.js 15 + MongoDB / Mongoose)  
**Date:** September 2026  

---

## 1. Architectural Philosophy & Data Segregation

The AgriShield 360° database architecture enforces a strict architectural boundary between two distinct categories of data:

1. **Category A: Agricultural Master Data (Reference & Botanical Foundation)**
   - Curated directly from the ICAR Annual Reports (2022–2026).
   - Immutable at runtime; read-heavy; cached globally.
   - Contains zero farmer-specific data.
   - All agronomic fields unsupported by ICAR (e.g., GDD, Base Temp) are explicitly **`null`**.

2. **Category B: Farmer Runtime Data (Dynamic Field & Monitoring Engine)**
   - Generated by farmer actions, satellite/weather observation feeds, and diagnostic scans.
   - High-write, indexed by `farmerId`, `fieldId`, `cropCycleId`, and temporal timestamps.
   - Connects to master data via normalized foreign references (`cropId`, `varietyId`, `growthStageId`).
   - Persists the output of the external **AgriVision Diagnostic Engine** (`POST /api/v1/diagnose`).

## 2. Category A: Agricultural Master Data Models

### 2.1 Model: `IcarCrop` (Crop Master)
- **Collection:** `icar_crops`
- **Purpose:** Botanical reference anchor for supported crops. Replaces ad-hoc crop name strings with an authoritative taxonomy.

```typescript
export interface IIcarCrop {
  cropId: string;              // Primary slug, e.g. "wheat", "rice", "cotton", "groundnut", "soybean"
  commonName: string;          // e.g. "Wheat"
  botanicalName: string;       // e.g. "Triticum aestivum"
  hindiName?: string;          // e.g. "गेहूं"
  cropType: 'Cereal' | 'Fiber' | 'Oilseed' | 'Pulse' | 'Horticulture';
  primarySeasons: ('Kharif' | 'Rabi' | 'Zaid' | 'Summer' | 'Boro')[];
  baseTemperatureC: number | null; // NULLABLE - Strictly null (0 ICAR citations)
  targetGdd: number | null;        // NULLABLE - Strictly null (0 ICAR citations)
  isPriorityCrop: boolean;     // true for the 5 MVP crops
  sourceReports: string[];     // ["ICAR-Annual-Report-2022-23", ...]
  active: boolean;
  createdAt: Date;
  updatedAt: Date;
}
```

### 2.2 Model: `IcarVariety` (Variety Master)
- **Collection:** `icar_varieties`
- **Purpose:** 654 verified cultivars extracted from ICAR Gazette notifications and trial releases.
- **Rule:** Contains zero fabricated GDD values. Duration is stored strictly as `maturityDaysMin` and `maturityDaysMax`.

```typescript
export interface IIcarVariety {
  varietyId: string;           // Compound slug: e.g. "wheat_hd-3298"
  cropId: string;              // References IcarCrop.cropId ("wheat")
  cropName: string;            // "Wheat"
  varietyName: string;         // "HD 3298"
  releaseYear?: number;        // e.g. 2023
  notificationNumber?: string; // S.O. gazette number if cited
  maturityDaysMin: number | null; // e.g. 110 (or null if unspecified)
  maturityDaysMax: number | null; // e.g. 115 (or null if unspecified)
  recommendedZones: string[];  // ["NWPZ", "NEPZ", "Punjab", "Haryana"]
  adaptationEcology?: string;  // "Timely Sown Irrigated (TS-IR)", "Rainfed"
  breedingInstitute?: string;  // "ICAR-IARI, New Delhi"
  keyTraits: string[];         // ["Biofortified", "High grain protein (12.2%)"]
  resistantTo: string[];       // ["Leaf Rust", "Stripe Rust"]
  baseTemperatureC: number | null; // NULLABLE - Strictly null
  gddToMaturity: number | null;    // NULLABLE - Strictly null
  sourceReport: string;        // "ICAR-Annual-Report-2023-24-English.txt"
  sourcePage?: number;
  sourceLineRange?: string;
  conflictStatus?: 'NONE' | 'RESOLVED_RANGE' | 'REQUIRES_REVIEW';
  active: boolean;
  createdAt: Date;
  updatedAt: Date;
}
```

### 2.3 Model: `CropGrowthStage` (Phenological Milestone Master)
- **Collection:** `crop_growth_stages`

- **Rule:** No BBCH decimal fabrication. No fake GDD accumulation limits.

```typescript
export interface ICropGrowthStage {

  dasEnd: number;              // e.g. 45
  gddStart: number | null;     // NULLABLE - Strictly null

  phenologicalSigns: string[]; // Characteristic visual vegetative markers
  waterStressSensitivity: 'LOW' | 'MEDIUM' | 'HIGH' | 'CRITICAL';
  vulnerablePests: string[];   // ["Termites", "Shoot Fly"]
  sourceReferences: string[];  // ICAR agronomic trial citations
  active: boolean;
  createdAt: Date;
  updatedAt: Date;
}
```

## 3. Category B: Farmer Runtime Data Models

### 3.1 Farm / Field Polygon Extension (`Field` Compatibility)
- **Strategy:** The existing `Field` model (`src/models/Field.ts`) remains 100% backwards compatible.
- **Additive Extension:** We add an optional `polygon` GeoJSON geometry field to `FieldSchema`:
```typescript
polygon: {
  type: {
    type: String,
    enum: ['Polygon', 'MultiPolygon'],
    default: undefined
  },
  coordinates: {
    type: Schema.Types.Mixed,
    default: undefined
  }
}
```
This enables full boundary mapping without altering any existing single-point fields.

### 3.5 Model: `CropDiseaseScan` (AgriVision Persistence Engine)
- **Collection:** `crop_disease_scans`
- **Purpose:** **Solves the `NOT_PERSISTED` gap in KisanDost.** Persists every diagnostic scan from the external AgriVision FastAPI service (`POST /api/v1/diagnose`) and attaches it to the specific crop, field, and growth milestone.

```typescript
export interface ICropDiseaseScan {
  farmerId: string;
  fieldId: mongoose.Types.ObjectId;      // Ref: Field
  zoneId?: mongoose.Types.ObjectId;      // Ref: FarmZone
  cropCycleId: mongoose.Types.ObjectId;  // Ref: CropCycle
  imageUrl: string;                      // Persisted image path or Cloud URL
  thumbnailUrl?: string;
  capturedAt: Date;
  location?: {
    latitude: number;
    longitude: number;
  };
  // AgriVision Diagnostic Output
  diagnosis: {
    primaryCondition: string;            // e.g. "Wheat Leaf Rust (Puccinia triticina)"
    pathogenType: string;                // "fungal" | "bacterial" | "viral" | "pest" | "deficiency"
    affectedPlantPart: string;           // "leaf" | "stem" | "grain" | "whole_plant"
    status: 'confirmed' | 'suspected' | 'healthy';
  };
  confidence: {
    level: 'High' | 'Medium' | 'Low';
    score: number;                       // e.g. 0.94
  };
  // AgriVision raw segmentation (if present)
  infectedAreaPct?: number;              // Raw area pct from segmentation
  // Clinical Severity (NULLABLE - AgriVision does NOT currently provide calibrated severity)
  severity: 'MILD' | 'MODERATE' | 'SEVERE' | 'CRITICAL' | null;
  // Agronomic Context at time of scan
  cropStageAtScan?: string;              // "Heading & Anthesis"
  dasAtScan?: number;                    // 72 DAS
  // Service Metadata
  serviceName: 'AgriVision Diagnostic Engine';
  serviceEndpoint: string;               // "https://...modal.run/api/v1/diagnose"
  rawResponsePayload?: any;              // Complete original JSON response
  remediationStatus: 'PENDING' | 'ACTION_TAKEN' | 'RESOLVED';
  createdAt: Date;
  updatedAt: Date;
}
```

### 3.8 Model: `RiskEvent` (Multi-Signal Risk Ledger)
- **Collection:** `risk_events`
- **Purpose:** Stores the output of the AgriShield Deterministic Multi-Signal Risk Engine.
- **Rule:** Uses deterministic, rule-based logic (combining DAS stage vulnerability + weather stress + AgriVision scan) rather than an unverified black-box AI model.

```typescript
export interface IRiskEvent {
  cropCycleId: mongoose.Types.ObjectId;  // Ref: CropCycle
  fieldId: mongoose.Types.ObjectId;      // Ref: Field
  zoneId?: mongoose.Types.ObjectId;      // Ref: FarmZone
  evaluationTimestamp: Date;
  daysAfterSowing: number;
  currentGrowthStage: string;            // e.g. "Panicle Initiation"
  // Risk Category
  riskCategory: 'STABLE' | 'ATTENTION' | 'HIGH_RISK';
  riskScore: number;                     // 0 to 100 calculated score
  // Multi-Signal Evidence
  contributingSignals: {
    stageVulnerability: {
      isVulnerable: boolean;
      vulnerablePests: string[];
    };
    weatherStress: {
      isTriggered: boolean;
      activeTriggers: string[];          // e.g. ["High Relative Humidity (>85%)"]
    };
    diseaseScanSignal: {
      hasActiveDiagnosis: boolean;
      latestScanId?: mongoose.Types.ObjectId;
      detectedCondition?: string;
      confidenceScore?: number;
    };
  };
  recommendedActions: Array<{
    category: 'CULTURAL' | 'IRRIGATION' | 'MONITORING' | 'PROTECTION';
    actionText: string;
    priority: 'ROUTINE' | 'URGENT';
  }>;
  createdAt: Date;
}
```

## 5. Summary & Database Ingestion Strategy
1. **Zero Overwrites:** Existing `Field.ts`, `Crop.ts`, `User.ts`, and `ScanHistory.ts` remain operational without schema breakage.
2. **Master Data Seeding:** A standalone seed script (`seed_phase1_master_data.ts`) will bulk insert the validated JSON files into `IcarCrop`, `IcarVariety`, `CropGrowthStage`, `PestDiseaseReference`, and `WeatherConditionReference`.
3. **Persisted Diagnostics:** Scans through `/api/detect-disease` will asynchronously create records in `CropDiseaseScan`, giving farmers a permanent diagnostic history in `/my-crops`.
